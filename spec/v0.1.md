# CRusty++ Language Specification — v0.1

> Status: **DRAFT.** This document becomes **FROZEN** when the design phase
> (Phase 0 in [`../ROADMAP.md`](../ROADMAP.md)) closes. Once frozen, it changes
> only to correct defects, never to add features.

This is the authoritative scope for `v0.1`. If a construct is not described here
(or in a sibling spec document referenced here), it is **not part of the
language**. Companion documents:

- [`syntax.md`](./syntax.md) — lexical structure and grammar
- [`memory-model.md`](./memory-model.md) — ownership, moves, borrows
- [`error-handling.md`](./error-handling.md) — errors, panics, exit codes

## 1. Overview

A CRusty++ program is one or more source files with the `.crust` extension,
compiled together as a whole. Execution begins at the function named `main`.

```crust
fn main() -> i32 {
    println("Hello, CRusty++!");
    return 0;
}
```

`main` must have the signature `fn main() -> i32`. Its return value is the
process exit code.

## 2. Lexical scope of v0.1

The following, and only the following, are in scope. Full grammar in
[`syntax.md`](./syntax.md).

### 2.1 Types

| Category | Types |
|----------|-------|
| Signed integers | `i8`, `i16`, `i32`, `i64` |
| Unsigned integers | `u8`, `u16`, `u32`, `u64` |
| Floating point | `f64` |
| Boolean | `bool` |
| Text | `str` (immutable UTF-8 string slice), `String` (owned, growable) |
| Unit | `()` (the empty type, implicit return of statement-only functions) |
| Aggregate | `struct` records (see §2.5) |
| Library types | `Option<T>`-shaped and `Result<T, E>`-shaped built-ins (see [`error-handling.md`](./error-handling.md)) |

There is **no** implicit numeric conversion. Conversions are explicit via `as`
(e.g. `x as i64`). Integer overflow behavior is defined in §6.

### 2.2 Literals

- Integer: `42`, `0`, `1_000` (underscores allowed as separators).
- Float: `3.14`, `1.0e9`.
- Boolean: `true`, `false`.
- String: `"hello"` with escapes `\n`, `\t`, `\\`, `\"`.
- Character escapes outside strings are not supported (no `char` type in v0.1).

### 2.3 Variables and bindings

```crust
let x: i32 = 10;        // immutable by default
let mut y: i32 = 0;     // mutable
```

- `let` introduces an immutable binding; `let mut` an mutable one.
- Type annotations are required on `let` in v0.1 (no inference of binding types).
- A binding's scope is the enclosing block; it is dropped at end of scope
  (see [`memory-model.md`](./memory-model.md)).

### 2.4 Functions

```crust
fn add(a: i32, b: i32) -> i32 {
    return a + b;
}
```

- Functions are **top-level only**. No nested functions, no closures.
- Every parameter is explicitly typed. The return type is explicit; a function
  with no `-> T` returns `()`.
- Recursion is permitted.
- There is no function overloading: a name maps to exactly one function.

### 2.5 Structs

```crust
struct Point {
    x: i32,
    y: i32,
}

let p: Point = Point { x: 1, y: 2 };
let a: i32 = p.x;
```

- Structs are flat records. No methods in v0.1 (free functions only).
- No inheritance, no subtyping. Field access uses `.`.
- Structs follow the ownership model: assigning or passing a struct **moves** it
  unless borrowed. See [`memory-model.md`](./memory-model.md).

### 2.6 Expressions and operators

- Arithmetic: `+ - * / %` on numeric types of matching type.
- Comparison: `== != < <= > >=` yielding `bool`.
- Logical: `&& || !` on `bool`, with short-circuit evaluation.
- Grouping: `( ... )`.
- Cast: `expr as Type`.
- Operands must already be the same type; there is no implicit promotion.

### 2.7 Statements and control flow

```crust
if cond {
    // ...
} else {
    // ...
}

while cond {
    // ...
}

let mut i: i32 = 0;
loop {
    if i >= 10 { break; }
    i = i + 1;
}
```

- `if` / `else`. The condition is a `bool` expression (no truthiness).
- `while`, and the infinite `loop` with `break` / `continue`.
- `return expr;` returns from a function.
- **No** `for`, no `match`, no `switch` in v0.1.

### 2.8 The prelude

A minimal set of built-ins is available without import:

- `println(s: str)` — write a line to standard output.
- `print(s: str)` — write without a trailing newline.
- `String` operations: construction from `str`, length, append (exact surface in
  [`syntax.md`](./syntax.md)).
- Built-in `Option`/`Result` constructors and the `?` propagation operator
  (see [`error-handling.md`](./error-handling.md)).

There is no other standard library in v0.1.

## 3. Memory and ownership

Memory safety is provided by the ownership model specified in full in
[`memory-model.md`](./memory-model.md). The v0.1 summary:

- Every value has exactly one owner.
- Assignment and function calls **move** non-trivial values, invalidating the
  source binding.
- Small `Copy` types (the scalar numeric types and `bool`) are copied, not moved.
- Borrows (`&T`, `&mut T`) are scoped and may not outlive their owner.
- Values are dropped deterministically at end of their owning scope.

## 4. Error handling

Errors are values. See [`error-handling.md`](./error-handling.md):

- Recoverable failures return a `Result`-shaped type.
- The `?` operator propagates errors.
- Unrecoverable failures call `panic(msg: str)`, which aborts the process.
- `main` returns `i32`; this value is the process exit code.

## 5. Modules and files

- A program is the set of `.crust` files passed to the compiler.
- v0.1 has **no module system, no imports, no namespaces.** All top-level names
  share one global namespace and must be unique across the program.

## 6. Defined behavior

CRusty++ aims to have **no undefined behavior** in the safe subset. In v0.1:

- **Integer overflow** in arithmetic operators is a defined runtime `panic`
  (checked arithmetic). `as` casts that truncate are defined to wrap.
- **Division or modulo by zero** is a defined runtime `panic`.
- **Out-of-bounds access** is not reachable in v0.1 because v0.1 has no indexable
  arrays or slices yet; this is revisited when collections are added.
- Reading a moved-from binding is a **compile-time error**, not a runtime fault.

## 7. Grammar

The complete grammar is in [`syntax.md`](./syntax.md). This document and the
three companion specs together define the entirety of `v0.1`. Anything not stated
is out of scope; see [`../NON_GOALS.md`](../NON_GOALS.md).

## 8. Conformance

A conforming `v0.1` compiler must:

1. Accept every program in [`../examples/`](../examples/) that is labeled valid.
2. Reject, with a diagnostic, programs that violate any rule above.
3. Implement the defined behaviors of §6 exactly (no UB substituted).

The conformance suite lives in [`../tests/`](../tests/).
