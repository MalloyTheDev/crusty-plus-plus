## 1. Overview

A CRusty++ program is one or more source files with the `.crust` extension,
compiled together as a whole. Execution begins at the function named `main`.

```crust
fn main() -> i32 {
    println("Hello, CRusty++!");
    return 0;
}
```

`main` must return either `i32` or `Result<i32, E>`. Its result determines the
process exit code (§4, [`error-handling.md`](./error-handling.md) §6). v0.1
examples use `fn main() -> i32` to keep exit behavior explicit.

## 2. Lexical scope of v0.1

The following, and only the following, are in scope. Full grammar in
[`syntax.md`](./syntax.md).

### 2.1 Types

| Category | Types |
|----------|-------|
| Signed integers | `i8`, `i16`, `i32`, `i64` |
| Unsigned integers | `u8`, `u16`, `u32`, `u64` |
| Pointer-sized unsigned | `usize` (lengths and sizes) |
| Floating point | `f64` |
| Boolean | `bool` |
| Text slice | `str` — an immutable UTF-8 text **view** (§2.5) |
| Byte slice | `[]u8` — an immutable byte **view** (§2.5) |
| Unit | `()` — the empty value; the implicit return of a function with no `->` |
| Aggregate | `struct` records (§2.6) |
| Core constructors | `Option<T>`, `Result<T, E>` — built-in only (§2.7) |
| Built-in error | `FileError` — returned by `read_all_bytes` (§2.9) |

There is **no owned `String` type in v0.1.** Text is represented by the borrowed
`str` view. An owned, growable string is deferred (see
[`../NON_GOALS.md`](../NON_GOALS.md)).

There is **no implicit numeric conversion.** Conversions are explicit via `as`
(e.g. `x as i64`, `bytes.len as i32`). Overflow behavior is defined in §8.

### 2.2 Literals and literal typing

- Integer: `42`, `0`, `1_000` (underscores are separators).
- Float: `3.14`, `1.0e9`.
- Boolean: `true`, `false`.
- String: `"hello"` with escapes `\n`, `\t`, `\\`, `\"`. A string literal has
  type `str`.

**Literal typing (frozen):**

- An **integer literal** takes the type required by its context — the other
  operand of an operator, a `let` annotation, a parameter type, or a `return`
  type. If no context constrains it, it defaults to **`i32`**.
- A **float literal** defaults to **`f64`** (the only float type in v0.1).

This contextual rule is the *only* type inference in v0.1; `let` annotations
remain mandatory (§2.3).

### 2.3 Variables and bindings

```crust
let x: i32 = 10;        // immutable by default
let mut y: i32 = 0;     // mutable
```

- `let` introduces an immutable binding; `let mut` a mutable one.
- A type annotation is **required** on every `let`.
- A binding's scope is the enclosing block.

### 2.4 Functions

```crust
fn add(a: i32, b: i32) -> i32 {
    return a + b;
}
```

- Functions are **top-level only**. No nested functions, no closures.
- Every parameter is explicitly typed. Parameters are **immutable bindings**.
- The return type is explicit; a function with no `-> T` returns `()`.
- Recursion is permitted. There is no function overloading.

### 2.5 Slices: `str` and `[]u8`

`str` and `[]u8` are **fat slices**: a (pointer, length) pair.

- A slice is **non-owning** — it borrows a view of memory it does not free.
- A slice is **non-null** and **immutable** in v0.1.
- A slice exposes a read-only field **`.len` of type `usize`** (the element
  count; for `str`, the length in bytes). The underlying pointer is **not**
  nameable in safe v0.1.
- `str` carries UTF-8 text but v0.1 provides no Unicode iteration/normalization
  APIs — it is a byte-accurate text view.
- **Indexing (`a[i]`) is not in v0.1.** Because there is no indexing, there is no
  out-of-bounds access to define. (Deferred; see [`../NON_GOALS.md`](../NON_GOALS.md).)

### 2.6 Structs

```crust
struct Point {
    x: i32,
    y: i32,
}

let p: Point = Point { x: 1, y: 2 };
let a: i32 = p.x;
```

- Structs are flat records. No methods (free functions only). No inheritance.
- Field access uses `.`.
- In v0.1 **structs are copied by value** (§7) — assigning or passing a struct
  duplicates it.

### 2.7 Core constructors: `Option<T>` and `Result<T, E>`

`Option<T>` and `Result<T, E>` are **built-in** tagged types:

```
Option<T> = Some(T) | None
Result<T, E> = Ok(T) | Err(E)
```

- They are the **only** types written with angle brackets in v0.1. The grammar
  recognizes exactly these two forms (`syntax.md` §6.4).
- This is **not** user-definable generics. Users cannot write `struct Foo<T>` or
  `fn id<T>(...)`. General generics remain a non-goal.
- Two core types are the **same type** iff their constructor and all type
  parameters are the same type (`Option<A> == Option<B>` iff `A == B`;
  `Result<A, X> == Result<B, Y>` iff `A == B` and `X == Y`).
- They copy by value like every v0.1 type (their tag and payload are copied).
- Construction and use are specified in [`error-handling.md`](./error-handling.md).

### 2.8 Expressions, operators, and evaluation order

- Arithmetic: `+ - * / %` on numeric operands of the **same** type.
- Comparison: `== != < <= > >=` yielding `bool`.
- Logical: `&& || !` on `bool`, short-circuiting.
- Cast: `expr as Type`.
- Grouping: `( ... )`.
- Operands must already be the same type; there is no implicit promotion (literal
  typing per §2.2 is resolved before this check).

**Evaluation order (frozen):**

- Expression evaluation is **strict left-to-right**.
- Function arguments are evaluated **left-to-right**.
- In an assignment `place = expr;`, the right-hand `expr` is fully evaluated
  **before** the target is mutated.

This order is normative: the C backend (§9) must preserve it during lowering.

### 2.9 Statements, control flow, and the prelude

```crust
if cond { /* ... */ } else { /* ... */ }
while cond { /* ... */ }
loop { if done { break; } }      // continue is also available
return expr;
```

- `if`/`else`, `while`, infinite `loop` with `break`/`continue`, and `return`.
- Conditions are `bool` expressions (no truthiness).
- **No** `for`, **no** `match` in v0.1.

The **frozen v0.1 prelude** (the entire library surface) is:

| Name | Signature | Purpose |
|------|-----------|---------|
| `print` | `fn print(s: str)` | write text, no newline |
| `println` | `fn println(s: str)` | write text + newline |
| `read_all_bytes` | `fn read_all_bytes(path: str) -> Result<[]u8, FileError>` | read a whole file |
| `is_ok` | `fn is_ok(r: Result<T, E>) -> bool` | test the `Ok` variant |
| `is_err` | `fn is_err(r: Result<T, E>) -> bool` | test the `Err` variant |
| `unwrap` | `fn unwrap(r: Result<T, E>) -> T` / `fn unwrap(o: Option<T>) -> T` | extract `Ok`/`Some`; **panics** if `Err`/`None` |
| `panic` | `fn panic(msg: str)` | abort the process (§4) |

Plus the built-in constructors `Ok`, `Err`, `Some`, `None`, and the built-in
type `FileError` (an opaque error with a read-only `.code: i32`). `is_ok` and
`is_err` are built-in over the core `Result` type; `unwrap` is built-in over both
`Result` and `Option`. None of these are user-callable generics. `Option<T>` has
no dedicated predicates (`is_some`/`is_none`) yet; inspect it via `unwrap`.

A function returning no value is written without `-> T` (it returns `()`); there
is no separate `void` keyword.

**Buffer ownership note.** `read_all_bytes` allocates a buffer and returns a
non-owning `[]u8` view of it. Because v0.1 has no owned/resource types and no
drops (§3, [`memory-model.md`](./memory-model.md) §0), that buffer is **not freed
in v0.1 — it is leaked** and lives for the rest of the process. This is an
accepted, documented limitation of the prototype; reclaiming it waits for
owned-buffer types in a later version. It is honest, not undefined: nothing reads
freed memory because nothing is freed.

There is **no other standard library** in v0.1.

## 3. Memory: copy semantics

See [`memory-model.md`](./memory-model.md) for the full statement. The v0.1
summary:

- Every v0.1 type is **copied by value**: scalars, `bool`, slices (`str`, `[]u8`
  copy the (ptr, len) view, not the underlying bytes), and `struct` records.
- There are **no resource-owning types** in v0.1, so there are no destructors and
  no move-checking in the first prototype.
- References (`&T`) exist in the grammar and are non-null, but examples and the
  first prototype do not require them; `&mut` is reserved.
- Ownership, moves, and drops are **documented design intent** for when
  resource-owning types are added later — not active v0.1 behavior.

## 4. Error handling

Errors are values. See [`error-handling.md`](./error-handling.md):

- Recoverable failures return `Result<T, E>`.
- The `?` operator propagates errors and is allowed **only** inside a function
  whose return type is `Result<T, E>`.
- `main` returns `i32` or `Result<i32, E>`; v0.1 examples use `i32`. Because
  `main` returns `i32` in examples, `?` is **not** used in `main`.
- Unrecoverable failures call `panic(msg: str)`, which **aborts** (no unwinding,
  no catch).
- Ignoring a `Result` value is **allowed** in v0.1 (a warning is a later concern,
  never an error).

## 5. Modules and files

- A program is the set of `.crust` files passed to the compiler.
- v0.1 has **no module system, no imports, no namespaces.** All top-level names
  share one global namespace and must be unique.

## 6. Mutability summary

- Local bindings and parameters are **immutable by default**; `let mut` opts a
  local into mutability.
- Assigning to a non-`mut` binding is a compile error.

## 7. Copy semantics (normative)

- **Scalars** (`i8`…`u64`, `usize`, `f64`, `bool`) copy.
- **Slices** (`str`, `[]u8`) copy their (pointer, length) view; the viewed bytes
  are not duplicated and not owned.
- **Structs** copy field-by-field.
- `Option<T>`/`Result<T, E>` copy when their payloads copy (true for all v0.1
  payload types).

Because all v0.1 types copy and none own a resource, no use-after-move analysis
is required for the first prototype. (This is revisited when resource-owning
types are introduced; see [`memory-model.md`](./memory-model.md) §0.)

## 8. Defined behavior

CRusty++ aims for **no undefined behavior** in the safe subset. In v0.1:

- **Integer overflow** in `+ - *` is a defined runtime **panic** (checked
  arithmetic).
- **Division or modulo by zero** is a defined runtime **panic**.
- **Signed negation overflow** (`-MIN`) is a defined runtime **panic**.
- **Division overflow** (`MIN / -1`) is a defined runtime **panic**.
- `as` casts between numeric types are **total and never panic**, with defined
  two's-complement behavior: widening sign-extends (signed source) or
  zero-extends (unsigned source); narrowing truncates to the target width;
  same-width sign changes reinterpret the bit pattern. (`as` is the explicit
  escape valve from checked arithmetic; see `../compiler/README.md`.)
- There is **no indexing** in v0.1, so there is no out-of-bounds access to
  define (§2.5).

## 9. Backend and generated C

The first implementation target is **portable C** (no LLVM, no WASM, no native
machine-code backend). The generated-C shape is specified in
[`../compiler/README.md`](../compiler/README.md) and summarized here:

- A CRusty++ function lowers to one C function.
- A `struct` lowers to a C `struct`.
- A slice (`str`, `[]u8`) lowers to `{ pointer, length }`.
- `Result<T, E>` and `Option<T>` lower to a tagged struct (tag + union/payload).
- `panic` lowers to abort-like behavior.

Generated C must be readable and debuggable, and must preserve the evaluation
order of §2.8. v0.1 makes **no ABI/layout stability guarantees** across versions.

## 10. Conformance

A conforming `v0.1` compiler must:

1. Accept every program in [`../examples/`](../examples/) and produce the
   documented behavior.
2. Reject, with a diagnostic (see [`../compiler/README.md`](../compiler/README.md)),
   programs that violate any rule above.
3. Implement the defined behaviors of §8 exactly (no UB substituted).

The conformance suite lives in [`../tests/`](../tests/).
